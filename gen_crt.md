# gen_crt — CRT Covering File Generator

`bin/gen_crt` generates the text CRT covering files that `bin/gapminer
--crt-file <file>` loads for CRT covering mode.

## What it does

A covering system chooses, for each small prime `p_i`, an offset `o_i`
(`0 <= o_i < p_i`) so that position `d` in `[1, gap_target)` is "covered"
(forced composite) when `d ≡ o_i (mod p_i)`. The optimizer greedily picks the
offset that covers the most still-uncovered positions, then runs a local
sweep to squeeze out more coverage. For the shipped files this covers ~93% of
`[1, gap_target)`.

The miner later solves the CRT alignment per block header so that
`base ≡ -(o_i + adj) (mod p_i)`, making that whole interior composite. Mining
at a **lower** live merit than the file's design merit then scans a window
`2 × needed_gap` that sits almost entirely inside the covered interior, so the
window is prime-poor and the consecutive-prime gap tail is stretched by ~1.27×
(`P(gap ≥ m) ≈ exp(-m/1.27)` instead of Cramér `exp(-m)`).

## Build

```bash
make bin/gen_crt
```

## CLI reference

```
Usage: bin/gen_crt --calc-ctr --ctr-primes N --ctr-file FILE [options]

  --calc-ctr            Calculate a CRT file (accepted for compatibility)
  --ctr-primes N        Number of CRT primes (2..200)
  --ctr-merit  M        Target merit (default 22.0)
  --ctr-bits   B        Extra bits: shift - log2(primorial) (default 0)
  --ctr-strength S      Greedy restarts / quality (default 50)
  --ctr-evolution       Enable evolutionary refinement
  --ctr-fixed  F        Primes frozen during evolution (default 8)
  --ctr-ivs    I        Population size for evolution (default 10)
  --ctr-range  R        Percent deviation from --ctr-primes (default 0)
  --ctr-file   FILE     Output CRT file (required)
  --help                Show this help message
```

The file's shift is computed automatically:

```
shift = ceil(log2(2 * 3 * 5 * ... * p_N)) + ctr_bits
```

`ctr_bits` is slack so the primorial stays below `2^shift` (the alignment
offset `nadd0 ∈ [0, primorial)` must fit the block's variable-length nAdd).

## Basic usage

```bash
# A single shift-720 / merit-23 covering file (98 primes, ctr-bits 8):
./bin/gen_crt --calc-ctr --ctr-primes 98 --ctr-merit 23 --ctr-bits 8 \
  --ctr-file my_crt.txt
```

This prints the chosen prime count, candidate count, shift and gap target:

```
wrote my_crt.txt  (98 primes, 1028 candidates, shift=720, gap_target=15560)
```

## Generating the whole set

```bash
mkdir -p data/crt/m23
for n in $(seq 67 130); do
  s=$(python3 -c "
import math
ps=[2]
m=3
while len(ps)<$n:
    if all(m%p for p in ps if p*p<=m): ps.append(m)
    m+=2
print(math.ceil(sum(math.log2(p) for p in ps))+8)
")
  ./bin/gen_crt --calc-ctr --ctr-primes "$n" --ctr-merit 23 --ctr-bits 8 \
    --ctr-file "data/crt/m23/shift${s}_p${n}_m23.txt"
done
```

Each file takes roughly a second (greedy + local sweep). 64 files ≈ one minute.

## Coverage quality vs. speed

- **Greedy + local sweep (default)**: ~93% coverage, ~1 s per file. Good enough
  for mining — the shipped files use this.
- **Evolutionary refinement (`--ctr-evolution`)**: a tournament/crossover/ILS
  pass that usually cuts a few more candidates, at the cost of ~5-10× the time.

```bash
# Higher-quality single file (slower):
./bin/gen_crt --calc-ctr --ctr-primes 98 --ctr-merit 23 --ctr-bits 8 \
  --ctr-evolution --ctr-strength 100 --ctr-ivs 20 --ctr-fixed 8 \
  --ctr-file my_crt_evo.txt
```

## File format

```
# CRT sieve file generated by gapminer gen_crt
n_primes 98
merit 23.00
shift 720
gap_target 15560
n_candidates 1028
2 1
3 2
5 2
...
```

The header is `n_primes / merit / shift / gap_target / n_candidates`, followed
by one `prime offset` pair per line. The convention: `offset o_i` is the
position `d ≡ o_i (mod p_i)` that is covered; the miner searches
`base ≡ -(o_i + adj) (mod p_i)`.

## Mining with the generated file

```bash
# GPU (fast — build with the CGBN kernel first):
make WITH_CUDA=1 WITH_CGBN_FERMAT=1
./bin/gapminer --crt-file my_crt.txt --enable-gpu-fermat \
  --enable-submission --coinbase-script-hex 76a914<20-byte-hash160>88ac \
  --host 127.0.0.1 --port 31397

# CPU (slower, deep sieve default 10M):
./bin/gapminer --crt-file my_crt.txt --host 127.0.0.1 --port 31397
```

See `README.md` → "CRT Covering Mode" for the full set of live-mining commands.

## Design-merit vs. live-merit

The covering is optimized for `gap_target = design_merit × logbase`. The miner
mines at the live node difficulty (`live_merit`). The boost appears when
`live_merit` is meaningfully **below** `design_merit`: the scan window
`2 × live_merit × logbase` then lies mostly inside the covered interior, so the
window is prime-poor. A file whose design merit equals the live difficulty
gives little or no boost — pick a design merit a few points above the expected
live difficulty (the shipped `m23` files target Gapcoin's ~22 difficulty).
